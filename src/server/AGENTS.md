- Live highlights (`src/server/live.server.ts`, pure `src/lib/live-detect.ts`): monitors advance under a fenced lease from the minute cron/open tab; YouTube polls liveChatMessages at the API's pollingIntervalMillis (needs YOUTUBE_API_KEY), Twitch reads chat via anonymous IRC samples (Helix status only via the Twitch connector); spike windows are upserted per (monitor,start). Hosted Workers cannot hold video streams, so media comes only from the user's own recorder worker (`public/recorder/recorder.py`, fetched by the Windows launcher built in `src/lib/recorder-launcher.ts`; token-hashed `/api/public/live/worker`, `status` heartbeat into `live_monitors.recorder_state`; buffer timing comes from ffmpeg CSV segment lists anchored to wall clock, because Windows ffmpeg cannot expand `%s` filenames; Streamlink output is sniffed by a relay and fed to ffmpeg with an explicit input format (ffmpeg pipe autodetection failed on Windows); fixture tests in `scripts/live-recorder/test_recorder.py`) for rights-confirmed monitors, verified by mp4-inspect and registered as an idempotent `route=live` job.
- Tab capture ("Следить и клипать вкладку", `src/lib/tab-capture.ts` + pure `src/lib/fmp4-cut.ts`): Chrome tab-only getDisplayMedia with required tab audio feeds one MediaRecorder fMP4 stream into a rolling keyframe-aligned buffer; highlights are cut by wall clock (−20 s/+15 s), claimed/finished via `captureClaim`/`captureFinish` and verified by the shared `finalizeHighlight`. One encoder + fragment splicing avoids re-encoding and overlapping recorders; Worker timers keep it running in a background tab.
